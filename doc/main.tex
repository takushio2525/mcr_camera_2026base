\section{概要}\label{sec:overview}

GR-PEACH (RZ/A1H) を使用した、マイコンカーラリー (MCR) カメラクラス開発のためのベースプログラムである。

\begin{notebox}[設計思想]
\begin{itemize}[nosep]
  \item mbed OS を使用せず、ルネサス標準の \texttt{iodefine.h} を用いたベアメタル（レジスタ直接操作）環境で構築する
  \item 既存のスパゲッティコードを廃し、EMA (Embedded-Module-Architecture) 準拠のモジュール分割を採用する。
        全モジュールは共通インターフェース \texttt{IModule} を実装し、
        \texttt{init()} / \texttt{updateInput()} / \texttt{updateOutput()} の3点で統一的に扱う
  \item モジュール間のデータ受け渡しは共有構造体 \texttt{SystemData} に一本化し、
        モジュールが他モジュールのメソッドを直接呼ぶことを禁止する
  \item 調整対象の定数は \texttt{src/core/ProjectConfig.h} に集約し、
        「走行調整のためにドライバのソースを触る」状況をなくす
\end{itemize}
\end{notebox}

\subsection{用語定義}

\section{背景・課題}\label{sec:background}

\begin{cautionbox}[開発環境の課題]
\begin{enumerate}[nosep]
  \item \textbf{mbed OS サービス終了}: mbed のサービス終了に伴い、将来的な継続利用や保守が困難になる
  \item \textbf{開発環境の老朽化}: 既存プロジェクトの e2 studio 環境やコンパイラバージョンが古く、最新の環境でビルドを通す必要がある
  \item \textbf{ブラックボックス化の解消}: OS内部処理への依存を減らし、デバッグを容易にする必要がある
\end{enumerate}
\end{cautionbox}

%% ============================================================
%% 3. 目的

\section{目的}\label{sec:purpose}

\begin{enumerate}[nosep]
  \item mbed OS に依存しない、RZ/A1H 用の C++ ベースプログラム環境の構築
  \item \textbf{クラス化・モジュール化}による可読性・保守性の向上
  \item 共通インターフェース (\texttt{IModule}) による統一的な制御フローの確立
\end{enumerate}

\section{システムアーキテクチャ}\label{sec:architecture}

システムは OSTM0 による 1ms 周期のタイマー割り込みで同期して動作する。
割り込みハンドラ \texttt{ostm0\_interrupt\_callback()} が
Input $\rightarrow$ Logic $\rightarrow$ Output の3フェーズを毎周期実行し、
メインループはフレーム完了待ち・ライン検出・ログ処理・デバッグ表示を担当する。

Input / Output の各フェーズは \texttt{IModule*} の配列 (\texttt{s\_inputModules[]} /
\texttt{s\_outputModules[]}) をループして呼び出す。
モジュールの \texttt{enabled} が \texttt{false} の間はスキップされるため、
初期化に失敗したモジュールを配列から外さずに無効化できる。

\begin{lstlisting}[caption={Input / Output フェーズの配列駆動 (mcr\_camera\_2026base.cpp)},label=lst:phasearray]
static IModule* s_inputModules[] = {
    &g_onboard,   // Input : SW 状態を sys.ob.sw へ
    &g_camera,    // Input : 1ms ごとのフレーム段階処理
};
static IModule* s_outputModules[] = {
    &g_motor,     // Output : sys.mot.*Cmd  -> PWM
    &g_servo,     // Output : sys.srv.angleCmd -> PWM
    &g_onboard,   // Output : sys.ob.*LedCmd  -> GPIO
};

for (int i = 0; i < N_IN; ++i) {
    if (s_inputModules[i]->enabled) s_inputModules[i]->updateInput(g_sys);
}
\end{lstlisting}

\subsection{3フェーズモデル}\label{sec:threephase}

\begin{tabularx}{\textwidth}{c l X}
\toprule
\textbf{順序} & \textbf{フェーズ} & \textbf{内容} \\
\midrule
1 & Input  & ハードウェア $\rightarrow$ \texttt{SystemData}。各モジュールの
             \texttt{updateInput(sys)} がセンサ値を \texttt{sys.*} へ書き込む \\
2 & Logic  & \texttt{SystemData} $\rightarrow$ \texttt{SystemData}。
             \texttt{applyDrivingPattern(sys)} が状態機械を進め、
             出力指示を \texttt{sys.mot.*Cmd} / \texttt{sys.srv.angleCmd} /
             \texttt{sys.ob.*LedCmd} へ\textbf{代入する}（\textbf{ドライバは呼ばない}） \\
3 & Output & \texttt{SystemData} $\rightarrow$ ハードウェア。各モジュールの
             \texttt{updateOutput(sys)} が \texttt{*Cmd} を読み、レジスタへ反映する \\
\bottomrule
\end{tabularx}

\begin{notebox}[3フェーズ分離の利点]
Logic フェーズはハードウェアに一切触れない純粋な計算になるため、
\texttt{SystemData} を差し替えるだけで PC 上の単体テストに載せられる。
また出力タイミングが Output フェーズに集約されるので、
1ms 内で出力が二度書きされたり、Logic の途中経過が物理出力に漏れることがない。
\end{notebox}

\begin{cautionbox}[全モジュールがラッチ方式ではない]
Output フェーズ内での反映方法はモジュールによって異なる。
\texttt{Onboard} は4個の LED 状態を内部バッファ \texttt{ledState\_[]} にまとめてから
GPIO へ一括書き込みする真のラッチ方式だが、
\texttt{Motor} / \texttt{Servo} は \texttt{updateOutput()} 内で MTU2 レジスタへ直接書き込む。
いずれも「Output フェーズでのみ書く」点は共通であり、
Logic フェーズの途中経過が出力に漏れない性質は保たれている。
\end{cautionbox}

\subsection{共有データ構造 SystemData}\label{sec:systemdata}

\texttt{SystemData}（\texttt{src/core/SystemData.h}）は全モジュールの入出力データを
1つに集約した構造体である。実体はグローバル変数 \texttt{g\_sys}
（\texttt{mcr\_camera\_2026base.cpp} で定義）1個のみで、
3フェーズの全呼び出しがこの参照を受け取る。

\begin{lstlisting}[caption={SystemData の定義},label=lst:systemdata]
struct SystemData {
    CameraData       cam;   // Camera       が所有
    LineDetectorData line;  // LineDetector が所有
    MotorData        mot;   // Motor        が所有
    ServoData        srv;   // Servo        が所有
    OnboardData      ob;    // Onboard      が所有
    EncoderData      enc;   // Encoder      が所有
    SerialData       ser;   // Serial       が所有
    SDLoggerData     sd;    // SDLogger     が所有
    RunData          run;   // RunLogic     が所有
};
extern SystemData g_sys;
\end{lstlisting}

\begin{notebox}[データの所有権]
\texttt{\{Module\}Data} 構造体の宣言は各モジュールのヘッダ側に置き、
\texttt{SystemData.h} はそれを include して集約するだけである。
各モジュールは原則として\textbf{自身の Data だけ}を読み書きし、
他モジュールのデータを横断参照してよいのは Logic フェーズの関数だけ、というルールで運用する。
\end{notebox}

\begin{cautionbox}[画素バッファは SystemData に置かない]
160$\times$120 の輝度バッファ（約 19KB）と YCbCr422 中間バッファ（約 38KB）は
\texttt{Camera} クラス内に実体を持ち、\texttt{SystemData} からは
\texttt{cam.imageBufferPtr} 経由で参照する。
巨大な配列を \texttt{SystemData} に持たせるとメモリ効率とコピーコストが悪化するため。
\end{cautionbox}

\subsection{ModuleTimer --- ノンブロッキング時間計測}\label{sec:moduletimer}

ベアメタル環境には Arduino の \texttt{millis()} に相当する API がないため、
OSTM0 の 1ms 割り込みでインクリメントされるグローバルカウンタ
\texttt{volatile unsigned long g\_timer\_1ms} を時刻源とする軽量クラスを用意している
（\texttt{src/core/ModuleTimer.h}）。

\begin{tabularx}{\textwidth}{l X}
\toprule
\textbf{メソッド} & \textbf{機能} \\
\midrule
\texttt{void setTime()}                    & 現在時刻を起点としてタイマーを開始する \\
\texttt{unsigned long getNowTime() const}  & \texttt{setTime()} からの経過時間 [ms]。未起動なら 0 \\
\texttt{bool isExpired(unsigned long ms) const} & 指定時間以上経過したか。未起動なら \texttt{false} \\
\texttt{void reset()}                      & 停止状態に戻す \\
\texttt{bool isRunning() const}            & 起動中かどうか \\
\bottomrule
\end{tabularx}

\vspace{2mm}
\texttt{RunData} はこれを3本保持し、旧実装のカウンタ変数を置き換えている
(\hyperref[sec:api-runlogic]{§\ref*{sec:api-runlogic}})。

\begin{notebox}[待ちループを書かないこと]
\texttt{ModuleTimer} は「経過したか」を問い合わせるだけで、内部でブロックしない。
1ms 割り込みの中で \texttt{while (!timer.isExpired(n))} のような待機を書くと
\texttt{g\_timer\_1ms} が進まなくなり、確実にハングする。
\end{notebox}

\subsection{設定注入と ProjectConfig}\label{sec:configinject}

各モジュールは \texttt{\{Module\}Config} 構造体を\textbf{コンストラクタ引数で受け取り}、
内部に \texttt{\_config} としてコピーして保持する。
実値の定義は \texttt{src/core/ProjectConfig.h} の1ファイルに集約されており、
走行パラメータの調整でドライバのソースを編集する必要はない。

\begin{lstlisting}[caption={Config 注入によるインスタンス生成 (mcr\_camera\_2026base.cpp)},label=lst:configinject]
Serial       g_serial      (SERIAL_CONFIG);
Onboard      g_onboard     (ONBOARD_CONFIG);
Motor        g_motor       (MOTOR_CONFIG);
Servo        g_servo       (SERVO_CONFIG);
Encoder      g_encoder     (ENCODER_CONFIG);   // 現状 init/呼出は未接続
Camera       g_camera      (CAMERA_CONFIG);
LineDetector g_lineDetector(LINE_DETECTOR_CONFIG);
SDCard       g_sdcard      (SDCARD_CONFIG);
SDLogger     g_sdlogger    (SDLOGGER_CONFIG);
\end{lstlisting}

実際の設定値は \hyperref[sec:params]{§\ref*{sec:params}}「パラメータ調整ガイド」にまとめる。

\begin{cautionbox}[Config はグローバル ctor に依存する]
\texttt{\_config} メンバはコンストラクタ初期化で埋まる。
本プロジェクトの \texttt{start.S} は \texttt{\_\_libc\_init\_array()} を呼ばないため、
\texttt{main()} 冒頭の \texttt{runGlobalConstructors()} を経由しないと
\texttt{\_config} が BSS のゼロのままになり、サーボ出力が 0 になる等の致命的な不具合になる。
詳細は \hyperref[sec:ctors]{§\ref*{sec:ctors}} を参照。
\end{cautionbox}

他のドライバとは異なり、ラッチ方式（\texttt{update()}による遅延送出）は採用せず、\texttt{printf} 呼び出し時に\textbf{即時出力（ポーリング送信）}を行う。これにより、途中クラッシュ時にもデバッグ出力を確実に得られるようにする。

\apisection{機能一覧}

\begin{itemize}[nosep]
  \item SCIF2 によるシリアル通信 (GR-PEACH USBシリアル通信ポート想定)
  \item 書式付き出力 (\texttt{printf})
  \item \textbf{即時出力}（バッファリングなし、ポーリング待機）
\end{itemize}

\apisection{内部定数}

\begin{tabularx}{\textwidth}{l l X}
\toprule
\textbf{定数名} & \textbf{値} & \textbf{説明} \\
\midrule
\texttt{BAUD\_RATE}   & 115200 & ボーレート \\
\bottomrule
\end{tabularx}

\apisection{内部変数}

特になし（バッファ状態を持たない）。

\apisection{関数ドキュメント}

\begin{funcblock}{init()}
\texttt{void init(void)}

\vspace{1.5mm}
SCIFの初期化（ピン設定、モジュールストップ解除、ボーレート設定等）を行う。
\end{funcblock}

\begin{funcblock}{update()}
\texttt{void update(void)}

\vspace{1.5mm}
\texttt{IModule} インターフェースを満たすためのダミー関数。何もしない。
\end{funcblock}

\begin{funcblock}{printf(fmt, ...)}
\texttt{void printf(const char* fmt, ...)}

\vspace{1.5mm}
書式付き文字列を即時送信する。\texttt{vsnprintf} を内部で使用し、\texttt{putChar()} を経由して文字を送信する。

\vspace{1.5mm}
\textbf{引数:} \texttt{fmt} (\texttt{const char*}) --- 書式文字列（\texttt{printf} 互換）
\end{funcblock}

\begin{funcblock}{putChar(c) \normalfont\small\color{gray}[内部]}
\texttt{void putChar(char c)}

\vspace{1.5mm}
1文字を即時書き込む。FIFO/送信レジスタに空きができるまで待機（ポーリング）してから送信する。
\end{funcblock}

\end{apibox}

\textbf{戻り値:} \texttt{uint8\_t} --- R1レスポンス
\end{funcblock}

\subsection{RunController クラス}\label{sec:api-runcontroller}

\begin{apibox}{RunController --- メイン走行制御モジュール（初心者向けベース）}

\textbf{ファイル:} \texttt{src/drivers/RunController.h}, \texttt{RunController.cpp} \hfill
\textbf{継承:} \texttt{IModule} \hfill
\phasebadge{Logic Phase}

\vspace{2mm}\hrule\vspace{2mm}

\apisection{概要}

参考プロジェクト \texttt{mcr\_shiozawa\_cclass\_2.38m-s/main.cpp} の \texttt{intTimer()} 内
\texttt{switch(pattern)} 状態遷移を移植したもの。
オリジナルでは「エンコーダ累積パルス」で距離管理していたが、
本実装では初心者が読みやすいようにすべて「経過時間 (ms)」で管理する。
各状態に入るたびに \texttt{stateMs\_} が 0 クリアされ、1ms 割り込みごとに 1 ずつ加算される。

\apisection{機能一覧}

\begin{itemize}[nosep]
  \item \texttt{Pattern} 番号による状態遷移（参考プロジェクトと同じ番号体系）
  \item スタートバー検出 → 通過 → 通常トレース → クランク/レーンチェンジ
  \item 各状態の遷移条件は経過時間（ms）で判定（距離不要）
  \item LineDetector の検出フラグを参照してクランク/ハーフラインを判別
  \item Motor / Servo / Onboard を直接制御
  \item 走行終了時に \texttt{isFinished()} で外部に通知（main 側でログ保存をトリガ）
\end{itemize}

\apisection{使用例}

\begin{lstlisting}[caption={RunController の組み込み例},label=lst:runcontroller]
// main 起動時
g_runController.init();

// OSTM0 1ms 割り込みコールバック内
extern "C" void ostm0_interrupt_callback(void) {
    g_camera.update();
    g_motor.update();
    g_servo.update();
    g_runController.update();   // 状態遷移を1ms毎に進める
    g_onboard.update();         // GPIO ラッチ反映
}

// メインループ
while (1) {
    if (g_camera.isFrameReady()) {
        g_camera.clearFrameReady();
        g_lineDetector.update(); // ライン検出はフレーム完了時のみ実行
    }
    if (g_runController.isFinished()) {
        g_sdlogger.saveToSD();   // 走行終了時にログ書き出し
        break;
    }
}

\subsection{割り込みハンドラ}

割り込みハンドラ関数内で各モジュールの \texttt{update()} を呼び出す。
\texttt{Pattern} 処理はクラス化せず、ハンドラ内にベタ書き（または関数化）する。

\begin{lstlisting}[caption={割り込みハンドラ実装例},label=lst:handler]
// グローバルインスタンス
static Onboard onboard;
static Motor motor;
static Servo servo;

void interrupt_handler() {
    // --- Input Phase ---
    // encoder.read();
    // camera.read();

    // --- Logic Phase (Pattern) ---
    int sw = onboard.sw();
    if (sw) {
        motor.setPower(0.2f, 0.2f);  // PWM 20%
        servo.setAngle(10.0f);       // 10度
        onboard.setLed(0, 1);        // Red ON
        onboard.setLed(1, 1);        // Green ON
        onboard.setLed(2, 1);        // Blue ON
    } else {
        motor.setPower(0.0f, 0.0f);
        servo.setAngle(0.0f);
        onboard.setLed(0, 1);        // Red ON
        onboard.setLed(1, 0);        // Green OFF
        onboard.setLed(2, 0);        // Blue OFF
    }

    // --- Output Phase ---
    motor.update();
    servo.update();
    onboard.update();
    // serial.update();
    // sd.update();
}
\end{lstlisting}
